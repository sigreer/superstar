  292	def classify_days(active_dates):
  293	    """Walk the inclusive calendar range over the active-day set and classify
  294	    each day. Returns an ordered list of:
  295	      ("day", date, is_active)                  -- a date marker (pill + divider)
  296	      ("quiet", run_start, run_end, n_days)     -- a collapsed run of >= QUIET_RUN_DAYS idle days
  297	    Idle runs only occur strictly between active days (the range is framed by the
  298	    first and last active day), so there is never a leading/trailing idle run.
  299	    """
  300	    if not active_dates:
  301	        return []
  302	    days = sorted(active_dates)
  303	    lo, hi, active = days[0], days[-1], set(days)
  304	    out, run = [], []
  305	    one = dt.timedelta(days=1)
  306	    d = lo
  307	    while d <= hi:
  308	        if d in active:
  309	            if run:
  310	                if len(run) >= QUIET_RUN_DAYS:
  311	                    out.append(("quiet", run[0], run[-1], len(run)))
  312	                else:
  313	                    out.extend(("day", r, False) for r in run)
  314	                run = []
  315	            out.append(("day", d, True))
  316	        else:
  317	            run.append(d)
  318	        d += one
  319	    return out
  320	```

    2	
    3	## Status
    4	
    5	Iteration on the shipped `tools/timeline` implementation. Extends — does not
    6	replace — `docs/specs/2026-06-06-X29-timeline-design.md` (the "base spec"). Only
    7	the deltas below change; everything in the base spec that is not contradicted
    8	here still holds. This is the acceptance-driven completion of slice **X29**: the
    9	human visual-acceptance gate surfaced two defects and one visual redesign, all in
   10	the date/gap/lane machinery.
   11	
   12	## Motivation
   13	
   14	Visual acceptance of the superstar render surfaced three items:
   15	
   16	1. **Bug — legacy phases share one spine instead of parallel lanes.** Phases that
   17	   ran concurrently in the day-precision era (e.g. superstar P3 ∥ P4, both
   18	   2026-05-19) collapse onto a single track; minute-precision phases (P5+)
   19	   separate correctly.
   20	2. **Bug — inactivity renders as a blank stop, not a dotted segment.** The
   21	   "N quiet days" bridge does not appear between phases; the spine just stops and
   22	   restarts.
   23	3. **Enhancement — dates clutter every card title.** Days are the primary unit of
   24	   measure, but the date is appended to each card/title face. The request: make
   25	   the day axis the spine's backbone and pull dates off the faces.
   26	
   27	Bugs 1 and 2 share a single root cause (below); item 3 is the day-axis redesign.
   28	
   29	## Part 1 — Day-precision end normalization (fixes Bug 1 and Bug 2)
   30	
   31	### Root cause
   32	
   33	Day-precision dates resolve to `00:00` of their day. That is correct for a
   34	**start/created** boundary but wrong for an **end/closed** boundary: it pins a
   35	legacy phase's close to the *start* of its day — before that same phase's
   36	minute-precision `started`, and before later same-day activity. Confirmed in
   37	superstar data:
   38	
   39	```
   40	P4  started = 2026-05-19 23:41 (minute)   closed = 2026-05-19 00:00 (day)
   41	```
   42	
   43	The phase interval is therefore **inverted** (`end < start`). Every consumer of
   44	phase intervals then misbehaves:
   45	
   46	- `_overlap_keys` / `assign_lanes` compare inverted intervals, so genuinely
   47	  concurrent legacy phases are not detected as overlapping → they share a lane →
   48	  **Bug 1**.
   49	- `quiet_gaps` merges coverage `(start, end)` where `end < start`, corrupting the
   50	  merge → gaps are mis-computed and the dotted bridge never renders → **Bug 2**.
   51	
   52	### Change
   53	
   54	Introduce a single notion of an **interval-effective instant** for a date value
   55	used as a *boundary*:
   56	
   57	- A boundary used as an **end/close** with **day** precision resolves to
   58	  end-of-day (`23:59:59` of that date).
   59	- A boundary used as a **start/created** with day precision stays at `00:00`.
   60	- Minute-precision values are unchanged in both roles.
   61	
   62	Apply it at every place that treats a date as an interval boundary, an ordering
   63	key, a scale anchor, or a **duration operand**: `phase_span` (the `end`), the
   64	span tuples feeding `assign_lanes` and `_overlap_keys`, the `anchors` list
   65	feeding `TimeScale`, slice/X **close** instants used for vertical positioning (so
   66	a day-precision close sorts *after* same-day minute-precision activity rather
   67	than before it), and the popout **duration computation** (`_duration_text`) — so
   68	the documented P4 case (minute-precision start later than a day-precision close
   69	on the same date) yields a real positive duration instead of an empty or
   70	inverted one. Day-precision *starts/creates* feeding duration stay at `00:00`.
   71	
   72	Note there is no `quiet_gaps` consumer in this list: Part 2 retires that
   73	hour-threshold API entirely (see below), so the only remaining interval/anchor
   74	consumers are lane assignment, overlap detection, the scale, positioning, and
   75	duration.
   76	
   77	**Display is unaffected.** `_fmt` already renders day-precision values with no
   78	time-of-day; the end-of-day instant is an internal sort/interval value only.
   79	Never surface a fabricated `23:59` (or `00:00`) in any label.
   80	
   81	Outcome: legacy intervals become well-formed → P3 ∥ P4 regain parallel lanes;
   82	coverage merges correctly → inactivity renders again (now via the day walk in
   83	Part 2).
   84	
   85	## Part 2 — Day-axis date spine
   86	
   87	The spine becomes an explicit **day axis**. This **retires** the base spec's
   88	hour-threshold gap bridge (`quiet_gaps` / `GAP_THRESHOLD_HOURS`) and the
   89	"completion date/time on every card" rule. Quiet rendering is now driven
   90	entirely by a **day-run classifier** over the active-day set (`QUIET_RUN_DAYS`),
   91	not by coverage-interval hour math; `quiet_gaps` and `GAP_THRESHOLD_HOURS` are
   92	removed, not reused.
   93	
   94	### Day walk
   95	
   96	Compute the set of **active days** = every calendar date carrying ≥1 **embedded**
   97	point event, using each event's local date. Embedded events are: phase starts,
   98	phase closes, slice closes, **and every embedded X close — regardless of the
   99	initial `--show-x` state**. Because X-items are always embedded and merely
  100	toggled client-side, X-only days are active days: each gets a date marker
  101	reserved exactly as X cards already reserve layout space while hidden. This is
  102	the F1 invariant — toggling X on can never reveal an X card on a day with no date
  103	pill, nor inside a collapsed quiet-run segment, because an X-only day counts as
  104	active and is therefore never part of an idle run. Walk the inclusive calendar
  105	range from the earliest to the latest active day:
  106	
  107	- **Active day** → one **date marker** on the spine: a faint full-width
  108	  horizontal divider hairline plus a date pill (`19 May 2026`) centred on the
  109	  spine. That day's cards/nodes hang off it as today, but **with the date removed
  110	  from the title/face**.
  111	- **Run of 1–2 consecutive idle days** (no active events) → each idle day still
  112	  gets its own empty date pill (divider + pill, no cards).
  113	- **Run of 3+ consecutive idle days** → collapse the entire run into one dotted
  114	  "N quiet days" segment with the count = number of idle days in the run. No
  115	  per-day pills inside a collapsed run.
  116	
  117	The threshold constant is named (e.g. `QUIET_RUN_DAYS = 3`).
  118	
  119	### Dates move to the popout
  120	
  121	- Card faces show **ID + title only** — no trailing date/time.
  122	- Phase node/title and close-ring labels drop their inline date clauses
  123	  (`started <date>`, `complete · <date>`); the day axis now carries that.
  124	- The **hover/click popout is unchanged**: full verbatim title, item ID,
  125	  started/closed datetimes **with precision markers**, and computed duration all
  126	  remain there. Exact times (`22:44`), durations, and minute precision survive
  127	  only in the popout.
  128	
  129	### Spacing (unchanged engine)
  130	
  131	The existing time-proportional `TimeScale` with min/max guard rails is retained
  132	unchanged — items keep their proportional vertical positions (busy days take more
  133	height; sparse days less). Date pills and dividers **overlay** the proportional
  134	layout: an **active day's** pill/divider sits at that date's first rendered event
  135	position; an **idle day's** pill (1–2-day runs) has no event to anchor to, so it
  136	is positioned by mapping that calendar day's local **noon** through `TimeScale`,
  137	keeping it between the surrounding active days. Pills and dividers do not quantize
  138	the scale into equal bands. A collapsed "N quiet days" run still compresses to the capped dotted
  139	segment, as the gap cap already does.
  140	
  141	### Direction toggle
  142	
  143	Date pills and divider hairlines are positioned for **both** reading directions
  144	and emitted with `data-ta`/`data-td` (and `data-ha`/`data-hd` for the divider
  145	spans) exactly like existing elements, so the in-page newest/oldest-first toggle
  146	flips them with everything else. Default remains newest-first.
  147	
  148	## Affected code
  149	
  150	- `render.py`: new interval-effective-instant helper used by `phase_span`, the
  151	  span tuples, `anchors`, close-instant positioning, and `_duration_text`. The
  152	  hour-threshold `quiet_gaps` / `GAP_THRESHOLD_HOURS` API is **removed**; a new
  153	  day-walk over the active-day set (including all embedded X closes) emits date
  154	  markers + dividers and classifies idle runs (`QUIET_RUN_DAYS`) into collapsed
  155	  quiet segments. `_card`, `_node_html`, `_ring_html` drop inline date clauses
  156	  from faces (popout/detail retains them).
  157	- No change to `extract.py`, `model.py` date resolution, `backfill.py`, or the
  158	  CLI surface. `--show-x` and overrides behave as before.
  159	
  160	## Testing
