1. Findings

F1. Severity: important — The spec says combined-gate guidance applies to every round, but does not define how round N+1 remembers the combined spec if the operator omits `--combined-gate`.
The document requires every combined-chain round to carry the guidance and stamp (`docs/specs/2026-06-09-P9.S3-combined-spec-plan-gate-design.md:125`, `:131`), but AC1 only asserts the round-1 request prompt (`:190-194`). In current code, incremental prompts are built from the current invocation’s `context` and `make_prompt` args (`skills/external-review/scripts/external-reviewer.py:3065`, `:3084-3088`), and the manifest currently has no chain-level field analogous to `work_id` that can restore the spec path on later rounds. This leaves two incompatible implementation paths: “caller must pass the flag every rerun” vs “chain persists and reuses the combined spec.” Without choosing one, round 2 can silently lose spec coverage while stats still classify the chain as combined from round 1.

F2. Severity: minor — The test location / coverage wording is internally inconsistent for AC6.
The design says workflow-step verification touches `tools/tasktool/` with a regression test and no production change expected (`docs/specs/2026-06-09-P9.S3-combined-spec-plan-gate-design.md:62-65`, `:183-186`), but AC8 says AC1-6 are covered by added tests in `skills/external-review/tests/` (`:216-217`). AC6 belongs naturally under `tools/tasktool/tests/`, because `_validate_set_flags` and `cmd_set` live in `tools/tasktool/commands.py` (`tools/tasktool/commands.py:80-125`, `:1223-1234`). As written, an implementer could satisfy one sentence and violate the other.
