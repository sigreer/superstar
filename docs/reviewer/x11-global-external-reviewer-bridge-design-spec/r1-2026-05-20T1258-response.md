# Review — docs/specs/2026-05-20-X11-global-external-reviewer-bridge-design.md

## Findings

**F1. Installer example hardcodes Simon's absolute checkout path. Severity: important.**
Section 1 shows the generated shim as:
```bash
exec python3 /home/simon/Dev/sigreer/skills/superstar/skills/external-review/scripts/external-reviewer.py "$@"
```
The spec calls this "analogous to `tools/tasktool/install.sh`", but `tools/tasktool/install.sh:29-30,53` self-locates via `SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"` and writes `PKG_ROOT="${PKG_ROOT}..."` derived at install time. The spec should mandate the same self-location pattern (compute the source path from the installer's own location) rather than illustrate with a literal user-specific path, otherwise the installer breaks for any other Superstar checkout (and the literal will get cargo-culted into the implementation). Restate the example with a `${SCRIPT_DIR}/scripts/external-reviewer.py`-style path and a note that no `/home/simon/...` strings should appear in the generated shim.

**F2. "Touches" includes `skills/external-review/scripts/external-reviewer.py`, but the body says it isn't modified. Severity: important.**
Section 1 only references the script; Non-goals (line 55) explicitly defers parser changes to X10; nothing in §§1–6 prescribes an edit to the source bridge. Either declare the intended change (e.g., adding a `--version`, exit-code adjustment, or shim-detection sentinel) or remove that path from the Touches list to avoid implementer confusion.

**F3. Project-setup classification has no detection rule for "vendored copy" vs "unknown script". Severity: important.**
Section 3 distinguishes three states (vendored copy, unknown script, compatibility shim). Only the shim has a marker (the `Compatibility shim for old Superstar handoffs` docstring + `external-reviewer` exec path). Without a stated detection rule, implementers will have to invent classification (hash match against the source tree? grep for `def chain_folder_name`? size threshold?), leading to drift. Recommended fix: collapse to two states — "documented compatibility shim" (matches marker) vs "anything else = legacy drift". The compatibility-pass case is then unambiguous and the partial case is trivially "not the shim".

**F4. Installer self-test assertion is path-coupled. Severity: minor.**
Tests subsection: "Test the shim points at `skills/external-review/scripts/external-reviewer.py` in this source checkout." If F1 is adopted (self-location), the assertion should be "shim contains an absolute path that resolves to the source `external-reviewer.py` of the running installer", not a literal substring. Restate.

**F5. Compatibility shim can self-loop if `PATH` resolution is unexpected. Severity: minor.**
`os.execvp(shutil.which("external-reviewer"), …)` is fine when `~/.local/bin` is on PATH, but if a future user puts a wrapper named `external-reviewer` earlier on PATH that itself shells back to `python3 scripts/external-reviewer.py`, the shim re-enters itself. Either add a one-line guard ("if `target` resolves under the calling repo, bail with a clear message") or document the PATH precedence assumption explicitly.

**F6. Acceptance criterion "project-setup reports … as legacy drift" implies a check that doesn't exist. Severity: minor.**
`skills/project-setup/SKILL.md` is markdown agent guidance; there is no CLI today (confirmed by Out-of-Scope follow-up #2). The acceptance criterion should clarify the actual mechanism: SKILL.md text + static wording tests assert the drift classification, and any future audit CLI is out of scope. Tighten wording so the criterion is testable as written.

**F7. Verification commands mutate `~/.local/bin` without an override. Severity: minor.**
`bash skills/external-review/install.sh` followed by `external-reviewer --help` (lines 368-369) writes/overwrites the user's actual bin. The Tests section already mentions "a temp `HOME` or configurable bin dir if the implementation adds such an override". Promote that override from optional to required (`EXTERNAL_REVIEWER_BIN` env var, or `--target DIR`), and rewrite the Verification snippet so it can be run unattended in CI/test contexts without clobbering the user's real shim.

**F8. Canonical example omits the `--work-id` conditionality. Severity: nit.**
`external-reviewer.py:1994` only requires `--work-id` for `post-slice`/`post-phase`. The canonical invocation in §Command Model lists it unconditionally; annotate it as required for post-slice/post-phase only, to match the bridge's actual contract.

**F9. `tools/tasktool/tests/test_skill_tasktool_lifecycle_docs.py` listed without justification. Severity: nit.**
File exists, but the spec doesn't say what is wrong with its current content. Confirm it references `scripts/external-reviewer.py` (grep) before listing it as a likely edit, or drop it.

**F10. The tasktool "source-tree semantics" claim is asserted without a citation. Severity: nit.**
Section 1 says "current `tasktool` already points at the source tree". Cite `tools/tasktool/install.sh` and the `PYTHONPATH=` line so implementers know exactly which precedent to mirror.
