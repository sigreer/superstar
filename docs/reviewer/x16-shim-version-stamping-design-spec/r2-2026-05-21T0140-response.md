1. Findings

F1. RESOLVED. Severity: blocking. The updated spec now explicitly preserves direct publish-side `external-reviewer` restamping and defines the source-root policy across direct publish, full deploy, and filtered deploy. See `docs/specs/2026-05-21-X16-shim-version-stamping-design.md:266`, `docs/specs/2026-05-21-X16-shim-version-stamping-design.md:275-277`, and the policy table at `docs/specs/2026-05-21-X16-shim-version-stamping-design.md:298-311`.

F2. RESOLVED. Severity: blocking. The spec now requires `plugins/superstar/VERSION` as a relative symlink to repo-root `VERSION`, and requires publish verification for `<cache>/<version>/VERSION` and `<cache>/current/VERSION`. This is grounded in the current Codex publisher using `plugins/superstar` as its source (`scripts/publish-to-local-codex.sh:54-55`) and using `rsync -aL` (`scripts/publish-to-local-codex.sh:94-96`). See `docs/specs/2026-05-21-X16-shim-version-stamping-design.md:262-275`.

F3. RESOLVED. Severity: important. The spec now defines shared header parsing and explicit `$HOME` / `~/` expansion before filesystem operations and copy-pastable diagnostics. See `docs/specs/2026-05-21-X16-shim-version-stamping-design.md:237-248`, plus the tasktool hook handshake update at `docs/specs/2026-05-21-X16-shim-version-stamping-design.md:201-203`.

F4. RESOLVED. Severity: important. The hook marker migration is now specified: `install.sh --hook` must accept either the legacy `tasktool-pre-commit-hook` marker or the new `superstar-hook-name: tasktool-pre-commit` marker, rewrite to the new header, preserve idempotency, and keep refusal for unrelated hooks. See `docs/specs/2026-05-21-X16-shim-version-stamping-design.md:220-235`.

F5. Severity: important. `deploy.sh --check` still lacks a complete failure contract for malformed or missing stamp state. Section 6b says missing or empty required keys are `MALFORMED`, distinct from `DRIFT` (`docs/specs/2026-05-21-X16-shim-version-stamping-design.md:247`), but the CLI contract and diagnostics section only promise a non-zero exit for `DRIFT` (`docs/specs/2026-05-21-X16-shim-version-stamping-design.md:282`, `docs/specs/2026-05-21-X16-shim-version-stamping-design.md:349`, `docs/specs/2026-05-21-X16-shim-version-stamping-design.md:404`). That leaves implementers free to print `MALFORMED` and still exit 0, which would let old unversioned shims or partially stamped installs pass the one-shot deploy gate even though acceptance criterion 3 requires all three global shims to carry stamp keys (`docs/specs/2026-05-21-X16-shim-version-stamping-design.md:396`). Specify whether `MALFORMED`, missing installed files, unreadable `VERSION` in cache rows, and missing source-root files are check-failing statuses, and add tests for their exit codes.

F6. Severity: minor. The acceptance criteria list now contains duplicate numbering and duplicate old entries, making the final gate set ambiguous. The new list runs 1-10 (`docs/specs/2026-05-21-X16-shim-version-stamping-design.md:394-403`), then the old 7-9 remain appended (`docs/specs/2026-05-21-X16-shim-version-stamping-design.md:404-406`). Collapse this into one canonical list so plan authors and reviewers do not have to infer which criteria supersede which.

2. Open questions / assumptions

- I assume `MALFORMED` is intended to be a failing deploy-check state for installed Superstar-controlled files, while runtime shims still exec normally when they cannot compare. The spec currently says the latter clearly but not the former.
- I assume `docs/tasklist.json` should keep X16 linked to the target spec. The current task entry has empty `refs` for X16 (`docs/tasklist.json:233-240`), which is not a spec correctness blocker but is a workflow hygiene issue.

3. Suggested document edits

- In §9, define the complete status lattice and exit behavior: for example, `OK` exits 0; `DRIFT`, `MALFORMED`, missing installed target after deploy, missing cache `VERSION`, and missing required source file exit non-zero; source-root mismatch with same version remains informational.
- Update test case 13 to assert `deploy.sh --check` exits non-zero on `MALFORMED`, not only that it prints a distinct row.
- Deduplicate acceptance criteria 7-10 and remove the stale repeated 7-9.
- Add `docs/specs/2026-05-21-X16-shim-version-stamping-design.md` back to X16 `refs` in `docs/tasklist.json` before closing the spec workflow.

4. Verification gaps / commands

- `bash tests/codex-plugin-sync/test-publish-to-local-codex.sh`
