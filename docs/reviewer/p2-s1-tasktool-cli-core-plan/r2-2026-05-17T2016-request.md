F2. Severity: blocking — The plan’s own stated end-to-end command cannot work.

F3. Severity: important — ID resolution does not meet the spec’s “short when unambiguous” contract.
The spec says CLI `<id>` arguments accept fully-qualified IDs or short forms when unambiguous (`docs/specs/...:162-164`, `176-178`). The planned `_find_item` rejects any short slice/task (`docs/plans/...:1674-1677`), and `cmd_create_task` requires a fully-qualified slice ID (`docs/plans/...:1493-1495`). Add resolution logic and tests for unambiguous `S1`/`T1`, plus rejection when ambiguous.

F4. Severity: important — Validation omits spec-required checks.
The spec requires ISO date format and path existence warnings for `spec_path`, `plan_path`, and `refs[]` (`docs/specs/...:166-174`). The planned validator only compares date strings lexically (`docs/plans/...:847-849`) and does not inspect path fields at all (`docs/plans/...:894-905`). Add concrete warning/error representation and tests for malformed dates and missing paths.

F5. Severity: important — Global CLI flags from the spec are missing.
The spec defines `--quiet`, `--verbose`, and `--no-stage` (`docs/specs/...:270-275`). The planned parser only has `--project-root` (`docs/plans/...:2377-2381`), and Task 14 stages on every save with no opt-out (`docs/plans/...:2612-2616`). At minimum, implement `--no-stage` or explicitly defer it.

F6. Severity: minor — The “all tests” command in Task 13 is likely a false gate.
