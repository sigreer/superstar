**Findings**

F1 — Severity: blocking  
`--state-file` is required by the spec for `review` and every state-touching subcommand, but the plan only implements env lookup in `state_file_path()` and adds `--state-file` to later subcommands. There is no task adding `--state-file` to the existing `review` command or testing `external-reviewer.py review --state-file ...`. See spec `docs/specs/2026-05-14-reviewer-rate-limit-handling-design.md:52` and plan `docs/plans/2026-05-14-reviewer-rate-limit-handling-plan.md:144`, `1849`, `2072`, `2260`.

F2 — Severity: blocking  
Slice 5 is not executable against the current script. The plan says “add a sub-parser” but current `parse_args()` uses `parser.add_argument("command", choices=["review"])`, not `subparsers` (`skills/external-review/scripts/external-reviewer.py:893`). It also calls nonexistent `resolve_chain_dir(...)` (`docs/plans/...:1871`, `2117`), calls `write_manifest(chain_dir, manifest)` even though the real signature expects the manifest file path (`skills/external-review/scripts/external-reviewer.py:285`), and treats `parse_verdict()` as a scalar even though it returns `(verdict, valid)` (`skills/external-review/scripts/external-reviewer.py:1503`). A worker following this will hit runtime errors.

F3 — Severity: blocking  
The rate-limited exit path writes a response artifact and raises `ReviewerRateLimited`, but the plan does not add the required `chain.json` round entry before exiting. Existing manifest append happens only after reviewer execution completes (`skills/external-review/scripts/external-reviewer.py:1407`), so raising from `run_one_reviewer()` at plan lines `1061-1067` bypasses the normal round write. This violates the spec’s requirement that rate-limited rounds are first-class chain entries (`docs/specs/...:125`) and leaves later resolution/preamble/coalescing logic without a head round to inspect.

F4 — Severity: important  
The sweep partial-rate-limit test/implementation is not grounded in the current sweep dispatch. The test relies on `REVIEWER_ROLE=sweep1` (`docs/plans/...:2357-2364`), but the script does not set that env var when calling sweep reviewers; sweeps are just additional `run_one_reviewer(...)` calls (`skills/external-review/scripts/external-reviewer.py:1353-1368`). The implementation sketch then refers to a fictional `for sweep_idx, sweep_cmd in enumerate(sweeps...)` loop (`docs/plans/...:2407-2434`). This needs to be rewritten around the actual `run_one_reviewer`/`ReviewerResult` flow.

**Open Questions / Assumptions**

I assume the plan is intended to be directly executable by worker agents using the included snippets. Under that assumption, placeholder-style lines like “existing helper” are plan defects, not harmless notes.

**Suggested Document Edits**

Add an early task to refactor `parse_args()` from positional `choices=["review"]` to real subparsers, preserving all existing review options and adding `--state-file` to `review`.

Add a concrete `resolve_review_chain(...)` helper task, or inline the existing `main()` chain resolution logic for `manual-approve` and `ingest-response`.

In Tasks 2.4/2.5, specify exactly how the rate-limited `chain.json` round is appended before exit 8, including `status`, `returncode`, `verdict`, `verdict_valid`, `request`, `response`, `reset_at`, and `reviewer_cmd`.

Rewrite Task 5.2 to unpack `verdict, valid = parse_verdict(reformatted)`.

Rewrite Task 5.4 around actual sweep execution: either pass a role marker into subprocess env deliberately, or use two different reviewer commands/templates in tests.

**Verification Gaps / Commands**
