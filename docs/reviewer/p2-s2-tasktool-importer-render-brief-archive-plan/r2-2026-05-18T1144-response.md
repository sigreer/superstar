1. Findings

F1. Severity: important  
[docs/plans/2026-05-17-p2-s2-tasktool-importer-render-brief-archive.md:1253](/home/simon/Dev/sigreer/skills/superstar/docs/plans/2026-05-17-p2-s2-tasktool-importer-render-brief-archive.md:1253) records the S2 plan link via `tasktool ref`, not `Slice.plan_path`. That conflicts with the model/spec and with this plan’s own renderer/brief code, which read `s.plan_path`, not `refs`. The final verification at line 1273 expects the brief to show the plan reference, but the proposed `brief()` implementation only prints `plan_path`, so the smoke test will fail or silently accept the wrong field. Add an explicit task to set or backfill `P2.S2.plan_path` after import, or add a small CLI command for updating plan paths.

F2. Severity: important  
[docs/plans/...:61](/home/simon/Dev/sigreer/skills/superstar/docs/plans/2026-05-17-p2-s2-tasktool-importer-render-brief-archive.md:61) and the importer/render snippets treat `blocked` as a generic status for all headings, including phases and cross-cutting items. The spec explicitly says only slices may be blocked, and current validation enforces that in [validate.py:74](/home/simon/Dev/sigreer/skills/superstar/tools/tasktool/validate.py:74) and [validate.py:87](/home/simon/Dev/sigreer/skills/superstar/tools/tasktool/validate.py:87). As written, importing a blocked phase/cross item would parse successfully and then fail during `_save`, while render can emit an invalid blocked phase without a tag. Narrow the status table and parser behavior by kind: blocked is valid only for slices; non-slice blocked input should produce a warning and a safe fallback or a deliberate import failure before write.

F3. Severity: important  
[docs/plans/...:311](/home/simon/Dev/sigreer/skills/superstar/docs/plans/2026-05-17-p2-s2-tasktool-importer-render-brief-archive.md:311) says archived/historical phase references are captured as `ArchivedPhase`, but the test at [line 335](/home/simon/Dev/sigreer/skills/superstar/docs/plans/2026-05-17-p2-s2-tasktool-importer-render-brief-archive.md:335) and migration check at [line 1181](/home/simon/Dev/sigreer/skills/superstar/docs/plans/2026-05-17-p2-s2-tasktool-importer-render-brief-archive.md:1181) expect `P1` to remain in `phases[]`. That is a concrete handoff ambiguity: an implementer could move P1 into `archived_phases[]` and break the stated migration acceptance. Pick one representation. Given the migration checks, the plan should remove the `ArchivedPhase` importer claim for historical P1 or make the checks expect `archived_phases[]`.

F4. Severity: important  
[docs/plans/...:1022](/home/simon/Dev/sigreer/skills/superstar/docs/plans/2026-05-17-p2-s2-tasktool-importer-render-brief-archive.md:1022) writes the archive markdown before [line 1029](/home/simon/Dev/sigreer/skills/superstar/docs/plans/2026-05-17-p2-s2-tasktool-importer-render-brief-archive.md:1029) validates and saves the updated project. If `_save()` fails validation, the command leaves an archive file on disk while `docs/tasklist.json` still has the phase active. Reorder the task so the final project state is validated before filesystem side effects, or write to a temp file and only rename after `_save()` succeeds.

F5. Severity: minor  
The archive-phase spec coverage says `--skip-review-gate` emits a stderr warning at [line 915](/home/simon/Dev/sigreer/skills/superstar/docs/plans/2026-05-17-p2-s2-tasktool-importer-render-brief-archive.md:915), matching spec §8.2, but the planned implementation only records a note via `_apply_review_gate` and returns `None`; the CLI test does not assert the warning. Add a return value or stderr path for the warning and test it.

2. Open questions / assumptions

I assume P1 historical work should remain in `phases[]` for ID continuity because Task 12 explicitly verifies that. If the desired end state is instead to put P1 in `archived_phases[]`, Task 12 needs to change.

I also assume S2 should not expand the public mutation surface unless needed. If adding `set-plan` is considered too much for S2, the migration task should use the documented raw-edit escape hatch for `plan_path`, not `refs[]`.

3. Suggested document edits

Change Task 13 to set `P2.S2.plan_path`, either with a new `tasktool plan <id> --set PATH` task or a raw-edit plus `validate --normalise`.

Clarify importer rules by item kind: phase/cross/task cannot import `blocked`; only slices can import `BLOCKED on ...`.

Resolve the historical/archive contradiction in Task 3 and Task 12.

Adjust archive-phase implementation ordering to avoid partial archive writes.

Add tests for skipped review gate warnings and for render/brief showing imported slice plan paths.
