  259	def _apply_landed_gate(
  260	    write_root: Path, qid: str, item, *,
  261	    allow_unlanded: bool, reason: str | None, command: str,
  262	) -> None:
  263	    """Refuse `done` for slice/cross rows whose recorded worktree branch has
  264	    not landed on the base branch (P8.S1 spec, D5-D7). `command` is the CLI
  265	    verb ("close" or "set") used in messages. With --allow-unlanded --reason,
  266	    records a timestamped audit note instead (mirrors the ready-close override).
  267	    """
  268	    kind = parse_id(qid)[0]
  269	    if kind not in ("slice", "cross"):
  270	        return
  271	    if getattr(item, "worktree_in_place", False):
  272	        return
  273	    branch = getattr(item, "worktree_branch", None)
  274	    if not branch:
  275	        return
  276	    if allow_unlanded:
  277	        if not reason or not reason.strip():
  278	            raise CommandError(f"{qid}: --allow-unlanded requires --reason")
  279	        ts = _dt.datetime.now().isoformat(timespec="seconds")
  280	        audit = f"[{ts}] allow-unlanded override for {qid}: {reason.strip()}"
  281	        item.notes = (item.notes + "\n" + audit).strip() if item.notes else audit
  282	        return
  283	    from tasktool import worktree as wt
  284	    parent = _authoritative_parent_branch(write_root, qid)
  285	    if not wt.branch_exists(write_root, branch):
  286	        raise CommandError(
  287	            f"{qid}: recorded worktree branch {branch!r} no longer exists; "
  288	            f"cannot verify it landed on {parent!r}. Any review/started gates "
  289	            f"already passed, but the {command} was NOT performed. If you know "
  290	            f"the work landed, re-run with --allow-unlanded --reason \"...\""
  291	        )
  292	    if not wt.branch_is_merged(write_root, branch=branch, into=parent):
  293	        raise CommandError(
  294	            f"{qid}: worktree branch {branch!r} has not landed on {parent!r}. "
  295	            f"Any review/started gates already passed, but the {command} was "
  296	            f"NOT performed. Merge back first:\n"
  297	            f"  cd {write_root}\n"
  298	            f"  git merge --no-ff {branch}   # or follow finishing-a-development-branch\n"
  299	            f"  tasktool {command} {qid} ...\n"
  300	            f"Escape hatch (records an audit note): --allow-unlanded --reason \"...\""
  301	        )

    1	# P8.S1 — tasktool close landed-branch gate + lifecycle auto-commit
    2	
    3	**Status:** spec (brainstormed 2026-06-05)
    4	**Slice row:** `P8.S1` · Phase doc: [`docs/specs/2026-06-05-P8-closeout-integrity-design.md`](2026-06-05-P8-closeout-integrity-design.md)
    5	**Motivating incident:** P7 closeout (2026-06-05) — see the phase doc. Two failure modes: (1) `tasktool close` marked P7.S5/S6 `done` while their worktree branches were unmerged ("done-but-not-landed"); (2) close left the tracker staged-but-uncommitted on the shared authoritative checkout, and concurrent closeout agents deadlocked on each other's co-staged mutations.
    6	
    7	## Design decisions (ratified during brainstorm)
    8	
    9	| # | Decision | Rationale |
   10	|---|----------|-----------|
   11	| D1 | Auto-commit scope: **close + worktree-prune state changes only** (completion paths and the prune-from-inside deferral). `start`, `cancel`, and other mutations keep today's stage-only behaviour. | P7 evidence: staged-`start` state was harmless. YAGNI; smallest blast radius matching the incident. |
   12	| D2 | On auto-commit failure: **warn loudly to stderr, exit 0**. The warning prints the exact `git commit` command to run manually. | The close itself is the critical mutation; a failed bookkeeping commit must not read as a failed close. Degrades to today's staged-state behaviour. |
   13	| D3 | The commit invariant is **"commit the lifecycle command's own authored paths, and nothing else"** — not "commit `docs/tasklist.json` only". For slice close/prune that is just `docs/tasklist.json`; for cross close with auto-archive it is the tracker **plus** the new `docs/archived-tasks/*.md`. | Leaving the archive file staged would recreate the dirty-authoritative-checkout problem under a different filename. (Refines the phase doc's literal "tasklist.json only" wording.) |
   14	| D4 | The commit helper is **explicit-path only**: it receives the paths the command just wrote/staged. It never infers "whatever is staged". | Keeps sibling-safety crisp; cannot absorb unrelated pre-staged artifacts. |
   15	| D5 | The unlanded-branch gate runs **after** the existing review/started gates, and its refusal message states that review validation passed but the close was **not** performed. | Behaviourally fine for review to validate first; the message must prevent "review passed so it must be done" misreadings. |
   16	| D6 | The gate applies to **slices and cross-cutting items** with a recorded `worktree_branch`. | `CrossCutting` rows carry `worktree_branch`/`worktree_in_place` too (`model.py:150`); a cross item can be done-but-not-landed by the identical mechanism. (Consistent extension of the phase doc's slice-only wording.) |
   17	| D7 | The gate also guards **`tasktool set <id> --status done`** (`cmd_set`, `commands.py:1108-1122`), with the same `--allow-unlanded --reason` escape hatch. Auto-commit is **not** extended to `set` (D1 scope). | `cmd_set` already mirrors close's review gate, started check, and `--allow-ready-close --reason` override; leaving it ungated would be an unlanded-branch bypass, defeating the phase goal that done-but-not-landed be unrepresentable. (Reviewer finding F1, r1.) |

   19	## Behaviour 1 — landed-branch close gate
   20	
   21	### Applicability
   22	
   23	In `cmd_close` (`tools/tasktool/commands.py:1160`) **and** in `cmd_set` when the requested status is `done` (`commands.py:1108-1122`; D7), the gate runs when **all** of:
   24	
   25	- the row's kind is `slice` or `cross` (phases and tasks have no worktree fields);
   26	- `worktree_in_place` is false;
   27	- `worktree_branch` is non-null.
   28	
   29	Exempt (close proceeds as today): in-place rows, rows with no recorded branch (never had a worktree, or already pruned), phases, tasks. `cmd_cancel` is untouched — cancelled work need not land. `set` with any status other than `done` is untouched.
   30	
   31	Both gated paths share one implementation: a `_apply_landed_gate(write_root, qid, item, *, allow_unlanded, reason)` helper called from `cmd_close` and `cmd_set`, mirroring how `_apply_ready_close_override` is shared today (`commands.py:1116`, `:1184`). `set --status done` keeps its existing stage-only persistence — auto-commit is not extended to it (D1/D7).
   32	
   33	### Check
   34	
   35	Reuse the P7.S4 helpers: `wt.branch_is_merged(write_root, branch=item.worktree_branch, into=_authoritative_parent_branch(write_root, qid))` (`worktree.py:253`, `git merge-base --is-ancestor`). If the branch is an ancestor of (or equal to) the base branch tip, the close proceeds.
   36	
   37	### Refusal
   38	
   39	If the branch is not landed, `cmd_close` raises `CommandError` **before any mutation** (`status` stays as-is; nothing is saved). The message must:
   40	
   41	1. state that the post-slice review gate passed (when it ran) but the close was **not** performed;
   42	2. name the branch and the base branch;
   43	3. print the merge-back commands, e.g.:
   44	   ```
   45	   cd <authoritative-root>
   46	   git merge --no-ff <worktree_branch>      # or follow finishing-a-development-branch
   47	   tasktool close <qid> ...
   48	   ```
   49	4. mention the escape hatch: `--allow-unlanded --reason "..."`.
   50	
   51	**Branch missing entirely** (recorded but deleted): `branch_is_merged` returns false because `merge-base` fails; the refusal message must distinguish this case — "branch '<name>' no longer exists; cannot verify landing. If you know it landed, re-run with `--allow-unlanded --reason`."
   52	
   53	### Escape hatch
   54	
   55	`tasktool close <id> --allow-unlanded --reason "..."` (and, per D7, `tasktool set <id> --status done --allow-unlanded --reason "..."`):
   56	
   57	- `--allow-unlanded` without a non-empty `--reason` is a `CommandError` (mirrors `_apply_ready_close_override`, `commands.py:701`).
   58	- On use, append a timestamped audit note to the row: `[<ISO ts>] allow-unlanded override for <qid>: <reason>` — same convention as the ready-close override.
   59	- Note: `--reason` is an existing close flag shared with `--allow-ready-close`; one `--reason` value serves whichever overrides are present in that invocation.

   61	## Behaviour 2 — lifecycle auto-commit
   62	
   63	### Helper
   64	
   65	```python
   66	def _git_commit_scoped(write_root: Path, rels: list[str], message: str) -> bool
   67	```
   68	
   69	- Runs `git commit -m <message> -- <rels...>` in `write_root` (a **pathspec commit**: git builds a temporary index from `HEAD` plus the named paths' working-tree content, commits only those paths, and leaves the real index — including any sibling staged entries — untouched). This is the mechanism that delivers D3+D4.
   70	- Explicit paths only (D4). Callers pass exactly what they authored.
   71	- Skipped entirely when `STAGE_AFTER_WRITE` is false (`--no-stage` implies no git side-effects) or when the new `--no-commit` flag is passed.
   72	- Returns success/failure. On failure (hook refusal, missing git identity, merge in progress, …): print a stderr warning containing the exact manual command (`git commit -m "<message>" -- <rels>`), and the command **exits 0** (D2).
   73	- No `--no-verify`: the pre-commit hook runs and validates the commit. Pathspec commits expose the temporary index to hooks via `GIT_INDEX_FILE`, so the hook's staged-content checks (`tasktool validate --strict-format` etc.) see exactly what is being committed; `_save` writes through the canonical serializer (`serialize.py` atomic write), so validation passes. Hook check #4 (staged spec/plan filenames must reference tasklist IDs) is unaffected — only the tracker (and, for cross close, the archive file) is committed.
