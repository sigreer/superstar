    1	# P8.S1 — tasktool close landed-branch gate + lifecycle auto-commit
    2	
    3	**Status:** spec (brainstormed 2026-06-05)
    4	**Slice row:** `P8.S1` · Phase doc: [`docs/specs/2026-06-05-P8-closeout-integrity-design.md`](2026-06-05-P8-closeout-integrity-design.md)
    5	**Motivating incident:** P7 closeout (2026-06-05) — see the phase doc. Two failure modes: (1) `tasktool close` marked P7.S5/S6 `done` while their worktree branches were unmerged ("done-but-not-landed"); (2) close left the tracker staged-but-uncommitted on the shared authoritative checkout, and concurrent closeout agents deadlocked on each other's co-staged mutations.
    6	
    7	## Design decisions (ratified during brainstorm)
    8	
    9	| # | Decision | Rationale |
   10	|---|----------|-----------|
   11	| D1 | Auto-commit scope: **close + worktree-prune completion only**. `start`, `cancel`, and other mutations keep today's stage-only behaviour. | P7 evidence: staged-`start` state was harmless. YAGNI; smallest blast radius matching the incident. |
   12	| D2 | On auto-commit failure: **warn loudly to stderr, exit 0**. The warning prints the exact `git commit` command to run manually. | The close itself is the critical mutation; a failed bookkeeping commit must not read as a failed close. Degrades to today's staged-state behaviour. |
   13	| D3 | The commit invariant is **"commit the lifecycle command's own authored paths, and nothing else"** — not "commit `docs/tasklist.json` only". For slice close/prune that is just `docs/tasklist.json`; for cross close with auto-archive it is the tracker **plus** the new `docs/archived-tasks/*.md`. | Leaving the archive file staged would recreate the dirty-authoritative-checkout problem under a different filename. (Refines the phase doc's literal "tasklist.json only" wording.) |
   14	| D4 | The commit helper is **explicit-path only**: it receives the paths the command just wrote/staged. It never infers "whatever is staged". | Keeps sibling-safety crisp; cannot absorb unrelated pre-staged artifacts. |
   15	| D5 | The unlanded-branch gate runs **after** the existing review/started gates, and its refusal message states that review validation passed but the close was **not** performed. | Behaviourally fine for review to validate first; the message must prevent "review passed so it must be done" misreadings. |
   16	| D6 | The gate applies to **slices and cross-cutting items** with a recorded `worktree_branch`. | `CrossCutting` rows carry `worktree_branch`/`worktree_in_place` too (`model.py:150`); a cross item can be done-but-not-landed by the identical mechanism. (Consistent extension of the phase doc's slice-only wording.) |
   17	
   18	## Behaviour 1 — landed-branch close gate
   19	
   20	### Applicability
   21	
   22	In `cmd_close` (`tools/tasktool/commands.py:1160`), the gate runs when **all** of:
   23	
   24	- the row's kind is `slice` or `cross` (phases and tasks have no worktree fields);
   25	- `worktree_in_place` is false;
   26	- `worktree_branch` is non-null.
   27	
   28	Exempt (close proceeds as today): in-place rows, rows with no recorded branch (never had a worktree, or already pruned), phases, tasks. `cmd_cancel` is untouched — cancelled work need not land.
   29	
   30	### Check
   31	
   32	Reuse the P7.S4 helpers: `wt.branch_is_merged(write_root, branch=item.worktree_branch, into=_authoritative_parent_branch(write_root, qid))` (`worktree.py:253`, `git merge-base --is-ancestor`). If the branch is an ancestor of (or equal to) the base branch tip, the close proceeds.
   33	
   34	### Refusal
   35	
   36	If the branch is not landed, `cmd_close` raises `CommandError` **before any mutation** (`status` stays as-is; nothing is saved). The message must:
   37	
   38	1. state that the post-slice review gate passed (when it ran) but the close was **not** performed;
   39	2. name the branch and the base branch;
   40	3. print the merge-back commands, e.g.:
   41	   ```
   42	   cd <authoritative-root>
   43	   git merge --no-ff <worktree_branch>      # or follow finishing-a-development-branch
   44	   tasktool close <qid> ...
   45	   ```
   46	4. mention the escape hatch: `--allow-unlanded --reason "..."`.
   47	
   48	**Branch missing entirely** (recorded but deleted): `branch_is_merged` returns false because `merge-base` fails; the refusal message must distinguish this case — "branch '<name>' no longer exists; cannot verify landing. If you know it landed, re-run with `--allow-unlanded --reason`."
   49	
   50	### Escape hatch
   51	
   52	`tasktool close <id> --allow-unlanded --reason "..."`:
   53	
   54	- `--allow-unlanded` without a non-empty `--reason` is a `CommandError` (mirrors `_apply_ready_close_override`, `commands.py:701`).
   55	- On use, append a timestamped audit note to the row: `[<ISO ts>] allow-unlanded override for <qid>: <reason>` — same convention as the ready-close override.
   56	- Note: `--reason` is an existing close flag shared with `--allow-ready-close`; one `--reason` value serves whichever overrides are present in that invocation.
   57	
   58	## Behaviour 2 — lifecycle auto-commit
   59	
   60	### Helper
   61	
   62	```python
   63	def _git_commit_scoped(write_root: Path, rels: list[str], message: str) -> bool
   64	```
   65	
   66	- Runs `git commit -m <message> -- <rels...>` in `write_root` (a **pathspec commit**: git builds a temporary index from `HEAD` plus the named paths' working-tree content, commits only those paths, and leaves the real index — including any sibling staged entries — untouched). This is the mechanism that delivers D3+D4.
   67	- Explicit paths only (D4). Callers pass exactly what they authored.
   68	- Skipped entirely when `STAGE_AFTER_WRITE` is false (`--no-stage` implies no git side-effects) or when the new `--no-commit` flag is passed.
   69	- Returns success/failure. On failure (hook refusal, missing git identity, merge in progress, …): print a stderr warning containing the exact manual command (`git commit -m "<message>" -- <rels>`), and the command **exits 0** (D2).
   70	- No `--no-verify`: the pre-commit hook runs and validates the commit. Pathspec commits expose the temporary index to hooks via `GIT_INDEX_FILE`, so the hook's staged-content checks (`tasktool validate --strict-format` etc.) see exactly what is being committed; `_save` writes through the canonical serializer (`serialize.py` atomic write), so validation passes. Hook check #4 (staged spec/plan filenames must reference tasklist IDs) is unaffected — only the tracker (and, for cross close, the archive file) is committed.
   71	
   72	### Call sites and commit messages
   73	
   74	| Command path | Authored paths | Commit message |
   75	|---|---|---|
   76	| `cmd_close` (slice/phase/task) | `docs/tasklist.json` | `<qid>: close <kind> (status=done)` |
   77	| `cmd_close` (cross, auto-archive) | `docs/tasklist.json` + `docs/archived-tasks/<file>.md` | `<qid>: close cross-cutting (status=done)` |
   78	| `cmd_worktree_prune` (normal completion) | `docs/tasklist.json` | `<qid>: prune worktree` |
   79	| `cmd_worktree_prune` (in-place completion) | `docs/tasklist.json` | `<qid>: prune worktree` |
   80	| `cmd_worktree_prune --finalize` | `docs/tasklist.json` | `<qid>: finalize worktree prune` |
   81	
   82	The prune-from-inside *deferral* path (`worktree_prune_pending`) also saves tracker state; it auto-commits the same way (message `<qid>: defer worktree prune`) so a deferred prune does not strand staged state either. `cmd_cancel` and `cmd_archive_cross` are deliberately out of scope (D1) and keep stage-only behaviour.
   83	
   84	### New flag
   85	
   86	`--no-commit` on `close` and `worktree prune` preserves the old stage-only behaviour for callers that batch several mutations into one hand-authored commit.
   87	
   88	## CLI surface changes

   90	- `tasktool close <id> [--allow-unlanded] [--no-commit]` (plus existing flags; `--reason` already exists).

   98	Gate:
   99	1. Unlanded branch → close refuses; message names branch+base, includes merge-back commands and "review passed / close not performed" framing; tracker unmodified.
  100	2. Landed branch (merged to base) → close succeeds.
  101	3. `worktree_in_place: true` → exempt.
  102	4. No recorded branch (already pruned) → exempt.
  103	5. Recorded branch deleted → refusal uses the "cannot verify landing" wording.
  104	6. `--allow-unlanded` without `--reason` → `CommandError`; with `--reason` → close succeeds and the audit note is on the row.
  105	7. Cross item with unlanded recorded branch → gated identically.
  106	
  107	Auto-commit:
  108	8. Close on a landed branch → `docs/tasklist.json` committed; `git status` clean for the tracker; commit message matches the table.
  109	9. Sibling-safety: pre-stage an unrelated file, then close → unrelated file remains staged and is **not** in the close commit.
  110	10. Cross close → commit contains tracker **and** archive file, nothing else.

  112	12. `--no-commit` → tracker saved + staged, no commit (old behaviour).

    1	# P8 — Closeout integrity: landed-branch close gate + lifecycle auto-commit
    2	
    3	**Status:** phase shaping (provisional — slice spec/plan writers ratify)
    4	**Phase row:** `P8` · Slices: `P8.S1`, `P8.S2`
    5	**Motivating incident:** P7 closeout (2026-06-05). P7.S5 and P7.S6 passed post-slice review and ran `tasktool close` → `status: done`, but neither session merged its worktree branch to `main`. The tracker said *done* while the deliverables existed only on unmerged `worktree-p7-s5/s6-*` branches; the P7 post-phase review returned `revise: S5/S6 unintegrated` and the human partner had to paste both sessions' transcripts into the S7-closeout session to untangle. Compounding it, both closeout agents saw each other's co-staged tracker mutations on the shared authoritative checkout and halted ("politeness deadlock"), and the recovery's `worktree prune --force` silently skipped the `landed_base_sha` stamp.
    6	
    7	## Phase objectives
    8	
    9	Make "done-but-not-landed" unrepresentable in practice, and remove the two behaviours that let it arise:
   10	
   11	1. **Close gate (tooling).** `tasktool close <slice-id>` refuses when the slice has a recorded `worktree_branch` that is not an ancestor of the base branch — i.e. the implementation has not landed. Escape hatch: `--allow-unlanded --reason "..."` (recorded on the row), mirroring the existing `reserve --force --reason` convention. Slices with `worktree_in_place: true` (no worktree) are unaffected.
   12	2. **Lifecycle auto-commit (tooling).** Tracker lifecycle mutations that today linger staged-but-uncommitted on the authoritative checkout (`close`, prune finalization) commit the tracker immediately as a scoped whole-file commit (`docs/tasklist.json` only). Rationale (human partner's ruling, 2026-06-05): the tracker is bookkeeping, not a body of work; both siblings' states are true regardless of which commit carries them, and lingering staged state is what triggered the concurrent-closeout deadlock.
   13	3. **Skill alignment (docs).** The slice-end sequence in `subagent-driven-development` gains a merge-back step (via `[[finishing-a-development-branch]]`) **before** `tasktool close`, in the same session; prune guidance says clean untracked files and never `--force` (a forced prune sets `merged_proven=False` and deliberately skips the `landed_base_sha` stamp, with no CLI path to stamp afterwards); `tasklist-discipline` distinguishes *sibling work artifacts* (hands-off) from *sibling tracker state in the shared canonical file* (safe to commit) so concurrent closeouts stop deadlocking.
   14	
   15	## Closeout goals
   16	
   17	- A slice with an unlanded worktree branch cannot reach `status: done` without an explicit, reasoned override.
   18	- `tasktool close` leaves the authoritative checkout clean (tracker committed), so a concurrent closeout never sees a sibling's staged mutation.
   19	- The documented slice-end sequence is: verification → post-slice review `ready` → merge-back to base → `close` (auto-commits) → clean prune (stamps `landed_base_sha`).
   20	- Docs-lifecycle test asserts the new prose; tasktool test suite covers the gate, the escape hatch, and the auto-commit.
