### docs/specs/2026-06-06-X29-timeline-design.md

    1	# X29 — Visual work-history timeline generator (`tools/timeline`)
    2	
    3	**Date:** 2026-06-06
    4	**Status:** draft
    5	**Kind:** cross-cutting tool (human-facing; zero agent-context footprint)
    6	
    7	## Purpose
    8	
    9	A script that generates a browser-viewable visual timeline of completed work for any
   10	tasktool-managed project, intended as a visual aid when discussing progress with
   11	non-technical people. A vertical spine down the centre of a scrollable page represents
   12	project time from start to latest activity; phases and slices are the major and minor
   13	nodes on that spine, placed at their completion dates/times.
   14	
   15	## Constraints (binding)
   16	
   17	- **Zero agent-context overhead.** No skill, hook, CLAUDE.md entry, or tasktool help
   18	  line references this tool. It is invoked only by humans or on explicit request in
   19	  interactive sessions.
   20	- **Zero dependencies.** Python 3 stdlib only; git accessed via `subprocess`. No
   21	  third-party packages, matching the repo's zero-dependency philosophy.
   22	- **Generic.** Works on any repo with `docs/tasklist.json` (current tasktool schema),
   23	  not just this one. Primary target project today: `multistore`.
   24	- **Static output.** A single self-contained HTML file (inline CSS/JS/data). Opens via
   25	  `file://`, shareable as an attachment, no server.
   26	
   27	## Placement & architecture
   28	
   29	```
   30	tools/timeline/
   31	  timeline.py    # CLI entry
   32	  extract.py     # git replay + live tasklist.json + archive JSON blocks → raw events
   33	  model.py       # the ONE schema-aware module → normalized TimelineItem records
   34	  render.py      # TimelineItem records → self-contained HTML
   35	  backfill.py    # run-once legacy migrator (separate command; never invoked by timeline.py)
   36	```
   37	
   38	Sibling to `tools/tasktool`, **not** part of it (tasktool's CLI surface is unchanged).
   39	`model.py` is the deliberate seam: it is the only module that knows the tracker schema.
   40	If a shared tracker-model module is later extracted from tasktool, only `model.py`'s
   41	internals are replaced; `extract.py` and `render.py` consume `TimelineItem` records and
   42	do not move.
   43	
   44	### CLI
   45	
   46	```
   47	python3 tools/timeline/timeline.py [--repo PATH] [-o timeline.html] [--show-x] [--overrides PATH]
   48	python3 tools/timeline/backfill.py [--repo PATH] [--write]
   49	```
   50	
   51	- `--repo` defaults to the current working directory's repo root (`git rev-parse --show-toplevel`).
   52	- `-o` defaults to `timeline.html` in the current directory.
   53	- `--show-x` sets the X-item toggle's initial state to on (data is embedded either way).
   54	- `--overrides` defaults to `docs/timeline-overrides.json` in the target repo if present.
   55	- `backfill.py` is dry-run by default, printing a unified diff; `--write` applies it.
   56	
   57	## Data model
   58	
   59	```python
   60	TimelineItem:
   61	  key            # "P21", "P21.S4", "X13"
   62	  kind           # phase | slice | x
   63	  parent         # phase key for slices, None otherwise
   64	  title          # verbatim tracker title
   65	  display_title  # optional override relabel; renderer prefers it when present
   66	  status         # done | cancelled | ready | in_progress | blocked ...
   67	  created, started, closed   # each: (datetime|None, precision, source)
   68	                             # precision: day | minute
   69	                             # source:    field | replay | override
   70	```
   71	
   72	## Date resolution (precedence)
   73	
   74	For each of `created`/`started`/`closed` on each item:
   75	
   76	1. **Overrides file** (`docs/timeline-overrides.json`, optional) — always wins. Schema:
   77	
   78	   ```json
   79	   {
   80	     "items": {
   81	       "P14":    { "started": "2026-05-20" },
   82	       "P21.S2": { "display_title": "Quiet-launch controls" },
   83	       "X12":    { "exclude": true }
   84	     }
   85	   }
   86	   ```
   87	
   88	   Values: ISO date or datetime for the three date fields; `display_title` string;
   89	   `exclude` boolean. Unknown keys in an item entry are an error (fail loud, not silent).
   90	
   91	2. **Tracker JSON fields** — the authoritative *date* (day precision). Sources: the live
   92	   `docs/tasklist.json` plus every archive file's `## Full phase JSON` fenced block under
   93	   `docs/archived-tasks/`. The placeholder `1970-01-01` is treated as absent. Where two
   94	   archive files exist for the same phase (legacy + tasktool re-archive), the one with a
   95	   parseable JSON block wins; pure-legacy markdown files are ignored by `timeline.py`
   96	   (they are `backfill.py`'s input, not the renderer's).
   97	
   98	3. **Git replay** — walk every commit touching `docs/tasklist.json` oldest→newest
   99	   (`git log --reverse --format=%H %ct -- docs/tasklist.json`), parse the file at each
  100	   revision (`git show SHA:docs/tasklist.json`), and record status transitions and date
  101	   field changes per item with the commit timestamp. Replay:
  102	   - upgrades a field date to **minute precision** when the replay-observed transition
  103	     falls on the same calendar day;
  104	   - fills a field that is null in the tracker (e.g. missing `started`: first transition
  105	     to `in_progress`/`started`; missing phase `closed` is *not* invented — an open phase
  106	     renders as open);
  107	   - **ignores transitions observed at an item's first-appearance commit when the item
  108	     appears already terminal** (import artifacts — e.g. the 2026-05-18 multistore
  109	     migration commit where P1–P12 arrived `done`).
  110	
  111	Validated against multistore: 226 commits replay with zero parse failures, yielding
  112	minute-precision lifecycles for 108 items.
  113	
  114	### Derived phase span
  115	
  116	- Phase start for rendering = `started` if present, else earliest slice `started`, else
  117	  phase `created`.
  118	- Phase end = `closed` if present, else open (strand runs to the bottom edge labelled
  119	  with the generation date).
  120	
  121	## Visual specification
  122	
  123	Validated interactively against real multistore data (P20–P23).
  124	
  125	- **Spine braid.** Vertical centre spine; one coloured strand per open phase. When N
  126	  phases are open concurrently, N strands sit side-by-side. When no phase is open, a
  127	  dotted grey strand bridges the gap with an "N quiet days" label. Phase colours come
  128	  from a fixed palette cycled by phase number (stable across regenerations).
  129	- **Nodes.** Phase start = filled disc in phase colour + bold title and start date.
  130	  Phase close = hollow ring in phase colour (grey ring for cancelled phases) + "PNN
  131	  complete · date" label. Slice completion = small filled disc in phase colour.
  132	- **Cards.** Each slice gets an info card tinted with the parent phase colour
  133	  (background tint + border), showing title (or `display_title`) and completion
  134	  date/time. Day-precision dates show no time-of-day (never a fake "00:00").
  135	  During solo stretches cards alternate left/right; during overlaps each open phase
  136	  owns one side so a track reads as a column. With 3+ concurrent phases the braid
  137	  gains strands; cards keep phase colours for attribution.
  138	- **Click-to-expand.** Clicking a card expands it in place: full verbatim title, item
  139	  ID, started/closed datetimes with precision markers, computed duration.
  140	- **Time scale: proportional with guard rails.** Vertical distance is proportional to
  141	  elapsed time, subject to (a) a minimum spacing between adjacent nodes — burst days
  142	  expand locally to stay readable — and (b) a maximum rendered height for empty
  143	  stretches — long gaps compress to a capped dotted segment with the quiet-days label.
  144	- **Cancelled items.** A cancelled phase is omitted unless it has ≥1 `done` slice; when
  145	  shown it renders normally (grey close ring), with only its completed slices.
  146	  Cancelled slices are always omitted.
  147	- **X-items.** First-class: always extracted and embedded. Rendered as neutral slate
  148	  nodes/cards on the spine at their completion time (they have no parent phase colour).
  149	  An in-page toggle shows/hides them instantly without regeneration; `--show-x` only
  150	  sets the toggle's initial state. Open/never-completed X-items are not rendered.
  151	- **Header.** Project name, overall date span, totals (phases completed, slices
  152	  completed), generation timestamp, and a colour legend of phases.
  153	
  154	## Legacy backfill (`backfill.py`)
  155	
  156	One-time, per-project migration for items that predate the tracker. It exists so that
  157	`timeline.py` never grows legacy parsing paths.
  158	
  159	- **Input:** legacy archive markdown under `docs/archived-tasks/` (headings of the form
  160	  `## S1 — title ✅ \`DONE 2026-04-29\``) and the repo's commit subjects.
  161	- **Recovers:** slice titles and close dates from the markdown; phase/slice `started`
  162	  dates from first-commit-mention mining (`\bP(\d+)(?:[.\-]?S(\d+))?\b` over subjects),
  163	  cross-checked against the previous phase's close for the sequential legacy era.
  164	- **Writes:** recovered slices and dates into the corresponding tasktool archive file's
  165	  `## Full phase JSON` block — the canonical location `tasktool unarchive` understands.
  166	  Phase-level fields already present are never overwritten.
  167	- **Safety:** dry-run by default with a unified diff; `--write` applies; the human
  168	  reviews and commits. Never invoked by `timeline.py`.
  169	
  170	Multistore evidence: legacy P1–P12 have reliable close dates in archives; commit mining
  171	dates P2–P12 starts cleanly; P1 has no commit mentions, so its `started` will need a
  172	manual override entry (or remain start-unknown, rendering from its close date only).
  173	
  174	## Error handling
  175	
  176	- Not a git repo / no `docs/tasklist.json` → clear fatal error.
  177	- A historical revision that fails JSON parsing → skipped with a stderr warning; replay
  178	  continues (validated: 0/226 failures on multistore, but schema drift must not be fatal).
  179	- Shallow clone → replay covers what exists; items degrade to day precision with a
  180	  one-line warning.
  181	- Unknown schema fields → ignored (tolerant reader); unknown override keys → fatal.
  182	- Items with no resolvable dates at all → listed in a stderr summary so gaps are
  183	  visible, omitted from the render. No silent drops.
  184	
  185	## Testing
  186	
  187	`tools/timeline/tests/` (pytest, mirroring tasktool's convention):
  188	
  189	- **Replay:** transition detection, minute-precision upgrade, null-fill, import-artifact
  190	  suppression — against a fixture git repo built by the test (tmpdir, scripted commits).
  191	- **Precedence:** override > field > replay; `1970-01-01` treated as absent; exclude.
  192	- **Braid:** lane assignment for 1/2/3 concurrent phases; gap detection.
  193	- **Scale:** guard-rail maths (min spacing under bursts, gap cap, proportionality
  194	  between guards).
  195	- **Backfill:** legacy heading parser; archive JSON block rewrite; dry-run diff output.
  196	- **Smoke:** end-to-end render of the fixture repo; assert expected node/card markup
  197	  and that the output is a single file with no external references.
  198	
  199	Out of scope: pixel/visual regression testing — the multistore render is eyeballed.
  200	
  201	## Non-goals
  202	
  203	- No tasktool subcommand, no shared module extraction now (the `model.py` seam bounds
  204	  that future change to one file).
  205	- No live server, no auto-refresh.
  206	- No LLM summarisation of titles (relabels are human-authored overrides).
  207	- No editing of tracker data by `timeline.py` (read-only; only `backfill.py --write`
  208	  mutates, and only archive files).
  209
