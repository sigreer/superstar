1. Findings

F1. Severity: important. Archived X-items are promised as first-class, but the extraction spec only names `## Full phase JSON` archive blocks.
`docs/specs/2026-06-06-X29-timeline-design.md:91-96` says archive extraction reads phase JSON blocks; `:147-150` says X-items are always extracted/embedded. In the actual archive format, X rows use `## Full cross-cutting JSON`, not phase JSON: `docs/archived-tasks/X16-stamp-installed-shims-and-enforce-versio.md:12-27`, and multistore uses the same format (`docs/archived-tasks/X7-backups-of-directus-content-beyond-postg.md:16-37`). Without specifying this, an implementer can satisfy the written extraction rule while silently dropping historical completed X-items, making the X toggle mostly empty.

F2. Severity: important. The test acceptance can be accidentally false-positive because the repo pytest discovery currently excludes `tools/timeline/tests`.
The spec places tests at `tools/timeline/tests/` (`docs/specs/2026-06-06-X29-timeline-design.md:185-197`) and acceptance says “All tests pass” (`:218`), but `pyproject.toml:1-3` currently sets `testpaths = ["scripts/tests", "tools/tasktool/tests", "skills/external-review/tests"]`. Unless the spec requires adding `tools/timeline/tests` to `testpaths` or running that directory explicitly, the default pytest gate can pass while timeline tests never run.

F3. Severity: minor. The legacy close-only rendering behavior is underspecified and internally inconsistent.
The derived phase span rules only allow phase start from `started`, earliest slice `started`, or `created` (`docs/specs/2026-06-06-X29-timeline-design.md:114-119`), while the legacy evidence says P1 may “remain start-unknown, rendering from its close date only” (`:170-172`). Multistore has exactly that shape in the tasktool archive: P1 has `created: "1970-01-01"`, `started: null`, no slices, and `closed: "2026-04-29"` (`docs/archived-tasks/P1-stabilise-sharewear-baseline.md:20-30`). The spec should say whether close-only phases render as a close node only, get a zero-length span, or are omitted with a warning.

2. Open questions / assumptions

- Should archived cross-cutting items be shown by default when the X toggle is enabled, or should some legacy/resolved X IDs be suppressible by default via overrides?
- For close-only legacy phases/slices, is “render from close date only” a supported display mode, or should backfill/overrides be required before they appear?
- Should the default verification command be `python3 -m pytest` after updating `pyproject.toml`, or an explicit targeted command such as `python3 -m pytest tools/timeline/tests tools/tasktool/tests`?

- In Testing or Acceptance, require updating `pyproject.toml` test discovery or name the explicit test command that includes `tools/timeline/tests`.
- In Derived phase span, add the close-only fallback/display rule for legacy items with no valid start/create date.
