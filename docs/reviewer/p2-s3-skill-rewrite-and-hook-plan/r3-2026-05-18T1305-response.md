**Findings**

F1 — RESOLVED — The plan now places the `--hook` branch before shim install logic and consistently invokes the installer with `bash`, not `sh`. See `docs/plans/2026-05-18-p2-s3-skill-rewrite-and-hook.md:312` and `:318`.

F2 — RESOLVED — The orphan validator now builds fully-qualified IDs only and includes a wrong-phase regression test for `P99.S1`. See `docs/plans/2026-05-18-p2-s3-skill-rewrite-and-hook.md:122` and `:162`.

F3 — RESOLVED — The hook plan now validates staged/index content by reading `:docs/tasklist.json` into a temp project root, with staged/worktree divergence tests. See `docs/plans/2026-05-18-p2-s3-skill-rewrite-and-hook.md:228`, `:269`, `:433`, and `:452`.

F4 — RESOLVED — The plan now preserves the existing `cmd_validate(..., format=...) -> tuple[int, str]` contract and the `{"ok", "errors", "warnings"}` JSON shape. See `docs/plans/2026-05-18-p2-s3-skill-rewrite-and-hook.md:175` and `:191`.

F5 — RESOLVED — `docs/tasklist.json` no longer falsely says the plan was set as `plan_path`; it records the plan in `refs` and explains why `plan_path` remains null. See `docs/tasklist.json:58`.

F6 — Severity: important — The new orphan filename parser does not correctly handle cross-cutting IDs. The regex only matches filenames beginning with a phase ID, and the example treats `2026-05-18-p2-x4-...` as “phase + cross”; however `tasktool` models cross-cutting IDs as top-level IDs like `X1`, and `collect_known_ids` adds only `X4`, not `P2.X4`. That means a filename shaped like the plan’s own example will be falsely rejected, while a natural top-level `2026-05-18-x4-...` filename will not be checked at all. See `docs/plans/2026-05-18-p2-s3-skill-rewrite-and-hook.md:105`, `:107`, and `:138`; current spec shows cross IDs as top-level at `docs/specs/2026-05-17-P2-tasktool-design.md:136`.

F7 — Severity: important — The planned hook installer is not actually idempotent. It detects an existing tasktool hook with `grep -q 'tasktool validate --strict-format'`, but the proposed template uses `tasktool --project-root "$TMP" validate --strict-format --format text`, so the sentinel string is absent. A second `bash tools/tasktool/install.sh --hook` run would reject the hook it previously installed unless `--force` is used. See installer check at `docs/plans/2026-05-18-p2-s3-skill-rewrite-and-hook.md:330` and template command at `:275`.

**Open Questions / Assumptions**

I assume cross-cutting items are allowed to have spec/plan filenames, because the skill rewrite explicitly tells users to create specs via `tasktool create phase|slice|cross ...`.

**Suggested Document Edits**

Add explicit cross-cutting filename rules and tests. Either support top-level `YYYY-MM-DD-x4-topic.md` as `X4`, or document that cross-cutting items do not participate in spec/plan filename orphan checks.

Change the installer sentinel to something stable in the template, for example a comment like `# tasktool-pre-commit-hook`, and grep for that exact marker. Add a test that runs `bash install.sh --hook` twice without `--force`.
