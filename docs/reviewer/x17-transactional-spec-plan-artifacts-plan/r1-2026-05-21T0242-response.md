1. Findings

F1 Severity: blocking  
`artifact status` treats staged files as unstaged, so `artifact commit` cannot pass its own post-staging gate. The spec says `artifact commit` stages referenced files and then runs `artifact status <id> --strict` so newly written artifacts can be accepted (`docs/specs/2026-05-21-X17-transactional-spec-plan-artifacts-design.md:153-167`). The plan’s `git_status_map` stores porcelain XY status, then flags any referenced path with a status other than `"  "` (`docs/plans/2026-05-21-X17-transactional-spec-plan-artifacts.md:617-629`, `679-680`). But `git status --porcelain` only lists changed paths; staged additions/modifications are `A ` / `M `, not `"  "`. After `cmd_artifact_commit` stages the artifact (`886-889`), the strict status call (`889-891`) will still report `referenced-artifact-unstaged` and refuse the commit. The plan needs explicit index/worktree-column handling: untracked `??` and unstaged worktree changes should fail; cleanly staged entries should not.

F2 Severity: important  
The implementation plan omits the spec’s target-slug orphan refusal for `artifact commit`. The spec requires `artifact commit` to “run a target-slug orphan scan” and defines deterministic slug matching rules (`docs/specs/2026-05-21-X17-transactional-spec-plan-artifacts-design.md:154-155`, `171-178`). Task 4 only adds an allowlist for staged paths and then commits (`docs/plans/2026-05-21-X17-transactional-spec-plan-artifacts.md:840-905`). That protects against unrelated staged code, but it does not catch an unreferenced sibling spec/plan/handoff/reviewer artifact for the same work item, which is one of the core failure modes X17 is supposed to address.

F3 Severity: important  
`--allow-missing` is not constrained to `spec|plan|handoff` in the proposed tasks. The spec permits missing paths only for `--kind spec|plan|handoff --allow-missing` (`docs/specs/2026-05-21-X17-transactional-spec-plan-artifacts-design.md:55`). The plan’s CLI accepts `--allow-missing` for all artifact kinds (`docs/plans/2026-05-21-X17-transactional-spec-plan-artifacts.md:445-451`), and `normalize_artifact_path` applies it uniformly (`209-229`). That would allow missing reviewer-chain or archive references, weakening the durable-reviewer-artifact boundary this change is meant to enforce.

F4 Severity: important  
Reviewer-chain directory orphan detection is specified but not implemented by the plan’s scan. The spec says unreferenced directories under `docs/reviewer/` must be reported (`docs/specs/2026-05-21-X17-transactional-spec-plan-artifacts-design.md:98-103`). The plan’s `_workflow_files` may add reviewer directories (`docs/plans/2026-05-21-X17-transactional-spec-plan-artifacts.md:649-657`), but the reporting filter only emits paths ending in `.md` or `chain.json` (`681-684`). A directory like `docs/reviewer/x17-...-plan/` will not be reported unless the code happens to inspect its `chain.json`, which does not satisfy the directory-reference contract and can miss the exact path agents are expected to register.

F5 Severity: important  
The plan does not cover the spec’s dirty-tasklist diagnostic. The spec requires `artifact status` to report “`docs/tasklist.json` changes that are unstaged while workflow artifacts are present” (`docs/specs/2026-05-21-X17-transactional-spec-plan-artifacts-design.md:103-105`). The planned `cmd_artifact_status` only checks referenced artifacts and unreferenced workflow files (`docs/plans/2026-05-21-X17-transactional-spec-plan-artifacts.md:663-687`). There is no tasklist-specific status check or test for this case, so the late-routing failure mode described in the spec remains partially invisible.

2. Open questions / assumptions

I assume `artifact status` is meant to report problems in the checkout where it is invoked unless called internally from `artifact commit`, which passes the authoritative `write_root`. If users are expected to run `artifact status` from linked worktrees and see authoritative state, the plan should say so explicitly and route that read path too.

3. Suggested document edits

Update Task 3 to define a small status parser that distinguishes staged, unstaged, and untracked states from porcelain XY columns, and add tests for a staged referenced artifact being clean.

Add a Task 4 helper and tests for target-slug orphan refusal before the commit command is considered complete.

Constrain `--allow-missing` in either CLI validation or `normalize_artifact_path`, and add a regression for `--kind reviewer --allow-missing` being rejected.

Revise `_workflow_files` / status rendering so reviewer-chain directories are first-class reported paths, not incidental `chain.json` files.

Add a strict-status test where `docs/tasklist.json` has unstaged changes while a workflow artifact exists.

4. Verification gaps / commands that should be run

The planned final gates are good, but they need the missing regressions above added before implementation starts:
