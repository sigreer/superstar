# P8.S1 — tasktool close landed-branch gate + lifecycle auto-commit

**Status:** spec (brainstormed 2026-06-05)
**Slice row:** `P8.S1` · Phase doc: [`docs/specs/2026-06-05-P8-closeout-integrity-design.md`](2026-06-05-P8-closeout-integrity-design.md)
**Motivating incident:** P7 closeout (2026-06-05) — see the phase doc. Two failure modes: (1) `tasktool close` marked P7.S5/S6 `done` while their worktree branches were unmerged ("done-but-not-landed"); (2) close left the tracker staged-but-uncommitted on the shared authoritative checkout, and concurrent closeout agents deadlocked on each other's co-staged mutations.

## Design decisions (ratified during brainstorm)

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Auto-commit scope: **close + worktree-prune state changes only** (completion paths and the prune-from-inside deferral). `start`, `cancel`, and other mutations keep today's stage-only behaviour. | P7 evidence: staged-`start` state was harmless. YAGNI; smallest blast radius matching the incident. |
| D2 | On auto-commit failure: **warn loudly to stderr, exit 0**. The warning prints the exact `git commit` command to run manually. | The close itself is the critical mutation; a failed bookkeeping commit must not read as a failed close. Degrades to today's staged-state behaviour. |
| D3 | The commit invariant is **"commit the lifecycle command's own authored paths, and nothing else"** — not "commit `docs/tasklist.json` only". For slice close/prune that is just `docs/tasklist.json`; for cross close with auto-archive it is the tracker **plus** the new `docs/archived-tasks/*.md`. | Leaving the archive file staged would recreate the dirty-authoritative-checkout problem under a different filename. (Refines the phase doc's literal "tasklist.json only" wording.) |
| D4 | The commit helper is **explicit-path only**: it receives the paths the command just wrote/staged. It never infers "whatever is staged". | Keeps sibling-safety crisp; cannot absorb unrelated pre-staged artifacts. |
| D5 | The unlanded-branch gate runs **after** the existing review/started gates, and its refusal message states that review validation passed but the close was **not** performed. | Behaviourally fine for review to validate first; the message must prevent "review passed so it must be done" misreadings. |
| D6 | The gate applies to **slices and cross-cutting items** with a recorded `worktree_branch`. | `CrossCutting` rows carry `worktree_branch`/`worktree_in_place` too (`model.py:150`); a cross item can be done-but-not-landed by the identical mechanism. (Consistent extension of the phase doc's slice-only wording.) |
| D7 | The gate also guards **`tasktool set <id> --status done`** (`cmd_set`, `commands.py:1108-1122`), with the same `--allow-unlanded --reason` escape hatch. Auto-commit is **not** extended to `set` (D1 scope). | `cmd_set` already mirrors close's review gate, started check, and `--allow-ready-close --reason` override; leaving it ungated would be an unlanded-branch bypass, defeating the phase goal that done-but-not-landed be unrepresentable. (Reviewer finding F1, r1.) |

## Behaviour 1 — landed-branch close gate

### Applicability

In `cmd_close` (`tools/tasktool/commands.py:1160`) **and** in `cmd_set` when the requested status is `done` (`commands.py:1108-1122`; D7), the gate runs when **all** of:

- the row's kind is `slice` or `cross` (phases and tasks have no worktree fields);
- `worktree_in_place` is false;
- `worktree_branch` is non-null.

Exempt (close proceeds as today): in-place rows, rows with no recorded branch (never had a worktree, or already pruned), phases, tasks. `cmd_cancel` is untouched — cancelled work need not land. `set` with any status other than `done` is untouched.

Both gated paths share one implementation: a `_apply_landed_gate(write_root, qid, item, *, allow_unlanded, reason)` helper called from `cmd_close` and `cmd_set`, mirroring how `_apply_ready_close_override` is shared today (`commands.py:1116`, `:1184`). `set --status done` keeps its existing stage-only persistence — auto-commit is not extended to it (D1/D7).

### Check

Reuse the P7.S4 helpers: `wt.branch_is_merged(write_root, branch=item.worktree_branch, into=_authoritative_parent_branch(write_root, qid))` (`worktree.py:253`, `git merge-base --is-ancestor`). If the branch is an ancestor of (or equal to) the base branch tip, the close proceeds.

### Refusal

If the branch is not landed, `cmd_close` raises `CommandError` **before any mutation** (`status` stays as-is; nothing is saved). The message must:

1. state that the post-slice review gate passed (when it ran) but the close was **not** performed;
2. name the branch and the base branch;
3. print the merge-back commands, e.g.:
   ```
   cd <authoritative-root>
   git merge --no-ff <worktree_branch>      # or follow finishing-a-development-branch
   tasktool close <qid> ...
   ```
4. mention the escape hatch: `--allow-unlanded --reason "..."`.

**Branch missing entirely** (recorded but deleted): `branch_is_merged` returns false because `merge-base` fails; the refusal message must distinguish this case — "branch '<name>' no longer exists; cannot verify landing. If you know it landed, re-run with `--allow-unlanded --reason`."

### Escape hatch

`tasktool close <id> --allow-unlanded --reason "..."` (and, per D7, `tasktool set <id> --status done --allow-unlanded --reason "..."`):

- `--allow-unlanded` without a non-empty `--reason` is a `CommandError` (mirrors `_apply_ready_close_override`, `commands.py:701`).
- On use, append a timestamped audit note to the row: `[<ISO ts>] allow-unlanded override for <qid>: <reason>` — same convention as the ready-close override.
- Note: `--reason` is an existing close flag shared with `--allow-ready-close`; one `--reason` value serves whichever overrides are present in that invocation.

## Behaviour 2 — lifecycle auto-commit

### Helper

```python
def _git_commit_scoped(write_root: Path, rels: list[str], message: str) -> bool
```

- Runs `git commit -m <message> -- <rels...>` in `write_root` (a **pathspec commit**: git builds a temporary index from `HEAD` plus the named paths' working-tree content, commits only those paths, and leaves the real index — including any sibling staged entries — untouched). This is the mechanism that delivers D3+D4.
- Explicit paths only (D4). Callers pass exactly what they authored.
- Skipped entirely when `STAGE_AFTER_WRITE` is false (`--no-stage` implies no git side-effects) or when the new `--no-commit` flag is passed.
- Returns success/failure. On failure (hook refusal, missing git identity, merge in progress, …): print a stderr warning containing the exact manual command (`git commit -m "<message>" -- <rels>`), and the command **exits 0** (D2).
- No `--no-verify`: the pre-commit hook runs and validates the commit. Pathspec commits expose the temporary index to hooks via `GIT_INDEX_FILE`, so the hook's staged-content checks (`tasktool validate --strict-format` etc.) see exactly what is being committed; `_save` writes through the canonical serializer (`serialize.py` atomic write), so validation passes. Hook check #4 (staged spec/plan filenames must reference tasklist IDs) is unaffected — only the tracker (and, for cross close, the archive file) is committed.

### Call sites and commit messages

| Command path | Authored paths | Commit message |
|---|---|---|
| `cmd_close` (slice/phase/task) | `docs/tasklist.json` | `<qid>: close <kind> (status=done)` |
| `cmd_close` (cross, auto-archive) | `docs/tasklist.json` + `docs/archived-tasks/<file>.md` | `<qid>: close cross-cutting (status=done)` |
| `cmd_worktree_prune` (normal completion) | `docs/tasklist.json` | `<qid>: prune worktree` |
| `cmd_worktree_prune` (in-place completion) | `docs/tasklist.json` | `<qid>: prune worktree` |
| `cmd_worktree_prune --finalize` | `docs/tasklist.json` | `<qid>: finalize worktree prune` |

The prune-from-inside *deferral* path (`worktree_prune_pending`) also saves tracker state; it auto-commits the same way (message `<qid>: defer worktree prune`) so a deferred prune does not strand staged state either. `cmd_cancel` and `cmd_archive_cross` are deliberately out of scope (D1) and keep stage-only behaviour.

### New flag

`--no-commit` on `close` and `worktree prune` preserves the old stage-only behaviour for callers that batch several mutations into one hand-authored commit.

## CLI surface changes

- `tasktool close <id> [--allow-unlanded] [--no-commit]` (plus existing flags; `--reason` already exists).
- `tasktool set <id> --status done [--allow-unlanded]` (D7; `--reason` already exists on the `set` parser, shared with `--allow-ready-close` — one value serves whichever overrides are present).
- `tasktool worktree prune <id> [--no-commit]` (plus existing flags).
- `tasktool close --help` text mentions the gate and both flags.

## Testing (TDD, `tools/tasktool/tests/`)

New test module `test_close_gate.py` plus extensions to existing prune/close coverage (`test_commands.py`, `test_pre_commit_hook.py` patterns for hook integration). Synthetic repos with a real worktree branch, following `test_start_worktree.py` fixtures.

Gate:
1. Unlanded branch → close refuses; message names branch+base, includes merge-back commands and "review passed / close not performed" framing; tracker unmodified.
2. Landed branch (merged to base) → close succeeds.
3. `worktree_in_place: true` → exempt.
4. No recorded branch (already pruned) → exempt.
5. Recorded branch deleted → refusal uses the "cannot verify landing" wording.
6. `--allow-unlanded` without `--reason` → `CommandError`; with `--reason` → close succeeds and the audit note is on the row.
7. Cross item with unlanded recorded branch → gated identically.
7a. `set --status done` with an unlanded recorded branch → refuses with the same gate; with `--allow-unlanded --reason` → succeeds and records the audit note (D7).
7b. `set --status <non-done>` on a row with an unlanded branch → not gated.

Auto-commit:
8. Close on a landed branch → `docs/tasklist.json` committed; `git status` clean for the tracker; commit message matches the table.
9. Sibling-safety: pre-stage an unrelated file, then close → unrelated file remains staged and is **not** in the close commit.
10. Cross close → commit contains tracker **and** archive file, nothing else.
11. Prune (normal, in-place, `--finalize`, deferral) → each commits with the right message.
12. `--no-commit` → tracker saved + staged, no commit (old behaviour).
13. Commit failure (inject a failing pre-commit hook) → close succeeded (status=done persisted), stderr warning includes the manual command, exit code 0.
14. `--no-stage` → no staging and no commit.
15. Real template hook (`tools/tasktool/templates/pre-commit-tasktool`) passes against an auto-commit (canonical serialization round-trip).

## Acceptance (refines phase doc)

- Full tasktool suite green.
- A synthetic unlanded-branch close refuses with actionable output.
- Close on a landed branch leaves `git status` clean for `docs/tasklist.json` (and for the archive file on cross close).
- The escape-hatch audit note renders on the row (`tasktool show`).

## Out of scope

- `start`/`cancel`/other mutation auto-commit (D1; P7 evidence says staged-start is harmless — revisit only if a future incident shows otherwise).
- Skill prose changes (`subagent-driven-development`, `tasklist-discipline`, prune guidance) — that is `P8.S2`, which depends on this slice and documents shipped behaviour.
- Any change to the pre-commit hook template or `install.sh`.

## Deviations from the phase shaping doc

1. Auto-commit scope renamed from "tracker lifecycle mutations" to **"lifecycle-authored files"** (D3): cross close also commits its archive artifact.
2. The gate covers **cross items** with recorded worktree branches, not only slices (D6).
3. Commit messages generalized per kind (table above) from the phase doc's slice-specific examples.
4. The gate also covers `tasktool set <id> --status done`, which the phase doc did not mention — leaving it ungated would have been a bypass (D7; reviewer finding F1, r1).
